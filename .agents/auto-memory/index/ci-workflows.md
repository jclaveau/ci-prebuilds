# ci-workflows — GHA mechanics, dispatch, promote gates, reading a run

Full hooks for this area. The routing keys live in `.agents/auto-memory/MEMORY.md`; the memories themselves in `.agents/auto-memory/<slug>.md`.

- [WebKit promote gate — RESOLVED](project_wk_promote_gate_holds_the_nightly_bench.md) — the three conformance-webkit blockers (camera/mic #112, CacheStorage #116, no-xserver #115) all landed; one dispatch off a COMBINED branch validated and promoted wk-latest, because promote-webkit fires on any dispatch with build_webkit=true
- [Promote gates differ per browser](project_promote_gates_by_browser.md) — chromium-from-source promotes chs-latest from ANY branch on a green dispatch; read the workflow at the run's head sha, not your checkout
- [TP paths-ignore can silently un-ship a fix](project_tp_paths_ignore_ships_nothing.md) — fastfmod/** and strip-bundled-libs.sh live under the ignored playwright/alpine-browsers/** path but the CONSUMER compiles them; also workflow_dispatch of test-and-publish never publishes, probe the run's own sha tag instead
- [GHA concurrency group serializes dispatches](project_gha_concurrency_group_serializes_dispatches.md) — `group: <name>-${ref}` + `cancel-in-progress: false` blocks parallel dispatches on the same branch (signature: status=pending, 0 jobs spawned); scope suffix by dispatch flavor when stages are independent
- [A force-push can leave a PR with ZERO runs](feedback_force_push_may_not_retrigger_ci.md) — after a rebase `gh pr checks` said "no checks reported" while the OLD sha's green runs sat in the timeline making it read as checked; assert a run exists at the NEW headSha, then kick with an empty commit
- [Dispatch expensive workflows via dispatch-once.sh](project_gha_dispatch_once_guard.md) — a lost `gh workflow run` reply is not a failed dispatch; it already ran server-side (a TLS timeout double-fired a probe). Refuses when one is live on the ref, confirms by watching for a NEW run id rather than believing the POST
- [A transient fetch reads as a code fault](project_transient_fetch_reads_as_code_fault.md) — fetch-aports.sh's own retries exhausting still fails the build, and BuildKit blames the changed file's `RUN` line, not the network; also an A/B pair dispatched together shares one outage window so both arms die at once — check the clock before blaming the diff
- [actionlint wrapper quirks](project_actionlint_wrapper_quirks.md) — `raven-actions/actionlint@v2` flag parser preserves literal `"` chars (can't pass spaced regex); `-ignore` matches `Error.Message`, not the `[rule-tag]` suffix — use no-space regex like `constant.expression`
- [gh run rerun single job](project_gh_run_rerun_single_job.md) — `gh run rerun --job N` restarts one failed job in-place while preserving upstream job outputs; saves 2h+ of chromium-from-source r1 when r2 hits a transient buildkit failure
- [CI metrics retention](project_ci_metrics_retention.md) — metadata complete since day one (2110 runs), logs 90 days (410 Gone beyond), billable=0 on a public repo so cost = runner-minutes, GHCR sizes never recorded and unreconstructable
- [Perf-branch build fixes rot on main](project_perf_branch_fixes_rot_on_main.md) — the chromium-151 gn peel lived only on perf/chromium-pgo-thinlto-1.62; main's from-source path was unbuildable ~3 months and dispatch-gating meant zero signal
- [FF ship path = push-to-main + choose_iter cold-flake](project_ff_ship_path_push_and_iter_flake.md) — merge push auto-builds+promotes ff-latest (no dispatch); dispatch builds but promote is push-gated → never ships; choose_iter fail-safes to cold ~4h on a transient manifest-inspect despite valid base (push run iter 10min vs my dispatch cold 4h, same SHA); PR #81 verified working
- [WebKit promote is unreachable with GTK off](project_wk_promote_unreachable_without_gtk.md) — default build ships an EMPTY minibrowser-gtk, conformance's headed leg can't pass, promote never fires; wk-2336/wk-latest were hand-promoted, which hid it
- [Auto-resolve-aports workflow + pre-flight rationale](project_auto_resolve_aports_workflow.md) — PR-time bump of ALPINE_APORTS_CHROMIUM_REF; pre-flight pkgver check exists because resolve script PREFIX-matches but `apply-and-build.sh` is strict; loop guard via actor + `[skip ci]`
- [chs from-source promote](project_chs_from_source_promote.md) — chs-<rev> = canonical (from-source, conformance-grade); apk retired to chs-apk-<rev>; promote-chromium-from-source.yml retags chs-fs→chs-<rev> no rebuild; consumer COPYs the tag, never builds; reuse-if-exists keyed on rev+recipehash
- [ci-watch script is branch-blind](project_ci_watch_branch_blindness.md) — `pnpm ci:watch:tp` latches on the latest TP run regardless of branch; use a targeted run-id poll after `git push origin main` if a parallel PR run is in flight
- [ff-latest stale on branches (no ff-edge)](project_ff_latest_stale_no_edge_tag.md) — promote-firefox is main-gated; ff-latest went months stale (pre pageerror-location patch) → headed FF conformance crashed `reading 'url'`; dispatch against fresh `sha-<gitsha>`, not ff-latest; propose a branch-promoted `ff-edge` tag
- [GHA API stale during long builds](project_gha_api_stale_during_long_builds.md) — `gh run view` reports `in_progress` 1-3h after actual completion on webkit producer runs; trust downstream conclusions + clock-elapsed, not headline status
- [On-demand prepare-failure UX](project_on_demand_prepare_failure_ux.md) — comment-close.if must be `always()`, not `prepare.result == 'success'`; separate prepare-fail step; every dispatch outcome → issue comment
- [Prepare action versioning](project_prepare_action_versioning.md) — consumed as `prepare@v0` (moving) / `@v0.1.0` (immutable); repo's FIRST git tags (ff-*/chs-* are image tags); on compatible action change bump v0.x.y + force-move v0; v1 reserved for repo-v1
- [Split tests by `needs:` not matrix](project_test_split_by_needs_pattern.md) — when matrix flavors pull different `build-*` deps, split into sibling jobs so the lighter side doesn't wait for the heavier (e.g., test-gha-tools-effects + test-gha-tools-hardened-effects)
