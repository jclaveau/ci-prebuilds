- [chromium residual: 12% after both knobs, static inspection exhausted](project_chromium_residual_gap_candidates.md) — dead: allocator, fonts, musl string routines, libc++ hardening, orderfile, CFI, TLS (non-component build = local-exec both sides), under-inlining (ThinLTO grew .text above official's); left = clang 22-vs-23 and runtime musl/glibc; next instrument is perf record, not another static candidate
- [chromium launch = the DSO closure; PartitionAlloc is fine](project_chromium_launch_dso_closure.md) — 43 DT_NEEDED vs 28, 1.87x per exec paid twice per launch(); allocator lead DEAD on both binaries; fix is a 25-30h cold rebuild so `perf record` first
- [chromium perf arms for 1.62 — PGO+ThinLTO together wins](project_chromium_perf_arms_1_62.md) — geomean vs official: baseline 1.42, PGO 1.28, ThinLTO 1.31, BOTH 1.12 (super-additive); layout 2.27/1.89/1.89/1.61; controls int_math+libm_fmod flat; ~38h build; chs-perf-ab prints official/ours, the inverse convention
- [The AVX2 string shim was a net loss — RETRACTED](project_chromium_faststring_moves_layout_text.md) — the layout_text win was measured on the artifact at `image_ours`, a DIFFERENT build from the consumer image (1.40x vs 1.14x on one runner); in the shipped image the shim costs `launch` 4.7-5.8% on two CPUs and moves layout_text not at all, so PR #201 unloads it. Also the bracketing lesson: an unbracketed A/B pair reported the controls 34-37% worse, and bracketed the same kernel is 44% FASTER
- [The official arm IS Chrome for Testing — flag-by-flag chain diff](project_chromium_cft_build_chain_diff.md) — CfT = Chrome release codebase + branding flags only, so the reference is a full official build; PGO profile/ThinLTO/lld are at PARITY and CFI+SSP diverge in our favour; the only live divergences left are Alpine clang 22 vs Chromium's pinned LLVM 23 and 17 system `.so`s outside the LTO+PGO unit (11 re-bundled by perf/chromium-unbundle-libs, text stack still out)
- [Chromium DCHECKs came from is_official_build=false](project_chromium_dcheck_from_is_official_build.md) — Chromium defaults `dcheck_always_on = !is_official_build`; layout 9.3× / DOM 7.2× slower than official, 77 DCHECK strings vs 0; aports uses is_official_build=true + pgo/lto/cfi off
- [The first chromium perf profile](project_chromium_perf_record_first_read.md) — screenshot is 100% PNG encode and NOT deflate (`libz` never appears on either arm); deflate is at PARITY (1.04x) and 66% of the overrun is one Skia raster-pipeline float family we run 6.3x more of, absent from the JPEG control which we WIN at 0.95x. layout is diffuse: +16% instructions at -13% IPC, musl ~19% of it. Alpine's default `-fstack-protector-strong` is real on the artifact (358 107 canary loads vs 33 166, 11.3x in the hot layout regions too) and prices at **+12.0% instructions** on a call-dense kernel
- [chromium's launch is the musl loader](project_chromium_launch_is_the_musl_loader.md) — first profile of the row: loader 49.4 vs 12.9 CPU-ms per launch = 71% of the whole delta, main binary at PARITY; musl binds every symbol in every object so 65 DSOs / 13,373 symbol relocs is the cost, and `--version` undercounts 3x because launch() execs browser+zygote+renderer
- [chromium's layout gap is diffuse — no hot function](project_chromium_layout_is_diffuse_no_hotspot.md) — the two layout kernels are confirmed two costs on ONE runner (1.47x reflow vs 1.31x boxonly); 94.9% of time is in the main binary but the hottest address anywhere is 0.38%, so profiling harder cannot find it and the lever is build config; plus: artifacts are stripped, sym.txt is truncated (do not sum it), and the PMU was absent on both arms twice today
- [The chromium screenshot cost is Skia's XR 10-bit decodes](project_chromium_screenshot_is_skia_highp.md) — dominated by `from_10101010_xr` (7.43%, int64->float that AVX2 emulates per lane), NOT `from_1010102_xr` (1.74%) — a 64 KiB bucket is not a function, anchor to the dispatch table; and the 66% was CANVAS-ONLY — on the campaign's real text page the XR family is ~17% of the main-binary delta, worth ~6% of the ratio, and only `--disable-gpu` removes it (breaks WebGL, so unshippable); PINNED: every 1010102/XR op is `HIGHP_ONLY` by construction, so an XR surface forces the float pipeline regardless of lowp — the raster fix is a SURFACE-FORMAT change, not a build flag (the 11.5x `vpmulhrsw` deficit is real but a separate question)
- [Alpine clang driver audit — closed](project_alpine_clang_driver_audit_closed.md) — the driver silently adds `-stack-protector 2`, `-fstack-clash-protection` and `_FORTIFY_SOURCE=2`; stack-clash emits ZERO probes on realistic C++ (.text byte-identical) and FORTIFY emits no `_chk` at all in C or C++, so SSP is the entire tax; also proves `-fstack-protector` is inert while `-Xclang -stack-protector -Xclang 1` takes guard-refs 3 to 0, and chromium's own BUILD.gn uses plain `-fstack-protector`
- [USE_SYSTEM_LIBS verdict](project_chromium_use_system_libs_verdict.md) — perf record killed the zlib leg (deflate at parity 1.04x), leaving `launch` alone: ~24 ms of a 64 ms gap, so 1.61 -> ~1.35-1.40, never <1.00 by itself; worth its OWN parallel arm, never a passenger in the fix chain (11 libraries in the direction aports doesn't test)
- [chromium gn perf knobs](project_chromium_gn_perf_knobs.md) — `is_official_build` defaults BOTH `use_thin_lto` and `chrome_pgo_phase=2` ON; PGO needs no depot_tools (public 83 MB profile + `pgo_data_path`); both under measurement on perf/chromium-{pgo,thinlto}
- [Our chromium calls musl's string routines; official carries its own](project_chromium_musl_string_routines.md) — nm -D: memcpy/memcmp/strlen undefined=1 on ours, absent on official; musl 3-30x slower at 64B-4KB; typed_array kernels are INERT (V8 never calls libc)
- [chromium's layout gap is in OUR binary, not libc](project_chromium_layout_gap_is_in_our_binary.md) — normalise perf DSO shares by the measured ratio first: main binary 1.31x carries 88-92% of the gap, libc only 6-10%; both binaries are stripped so the 90% is unattributed, the PMU was refused so IPC is still open, and `layout_text` checksums DIFFER between arms so that row compares two renderings
- [Alpine clang forces SSP strong from the DRIVER](project_alpine_clang_forces_ssp_strong.md) — `-fstack-protector` and `--no-default-config` are both INERT (`-###` shows cc1 getting `-stack-protector 2` regardless); only `-Xclang -stack-protector -Xclang 1` reaches cc1, and 1 is exactly official chromium's posture — use it, never `-fno-stack-protector`, which would leave us less protected than the reference
