Full hooks for this area. The routing keys live in `.agents/auto-memory/MEMORY.md`; the memories themselves in `.agents/auto-memory/<slug>.md`.

- [PW's WebKit base lags the browser it ships](project_pw_webkit_base_lags_shipped_build.md) — v1.62.0's UPSTREAM_CONFIG names an April WebKit but the shipped webkit-2336 is past `5e67bf8293`; `protocol.json` inside PW's zip is the authority (21 settings vs our 20) — root cause of the PushAPIEnabled newPage failure
- [WebKit CacheStorage records are unreadable — RESOLVED](project_wk_cachestorage_disk_records_invisible.md) — PW's bootstrap.diff patches decodeForPersistence to read httpRequestHeaderFields but never adds the encoder line, so every record we write is 8 bytes short and no build reads it back; shared-profile probe is the experiment
- [WebKit page.close() hangs — missing Playwright.closePage](project_wk_closepage_hang.md) — PW's published bootstrap.diff omits the command (all tags + main); sendMayFail swallows -32601, page never closes, `Page._close()` blocks on closedPromise; complete gap = closePage + partitionKey ×2; fixed b49430e
- [WebKit strip + GTK gate + promote](project_webkit_strip_gtk_gate_promote.md) — 2026-08-01: finalize strips ELF symbols (WPE-only), GTK gated off by default (`build_webkit_gtk`); GTK skip cascade-skipped smoke/promote → `!cancelled()` fix (1752fc1, not yet CI-validated); promote tags wk-REV/wk-VER/wk-latest on GHCR + Docker Hub (both promoted manually to digest 0ec9157ad; cross-registry copy is a multi-GB blob transfer, not a fast manifest PUT)
- [MiniBrowser drops its settings on --no-startup-window](project_wk_minibrowser_no_startup_window.md) — PW passes it for every non-persistent launch and `activate()` returns before building the settings object, so `--features` and every settings default reach no PW-created page; persistent takes the `--user-data-dir` branch instead and is NOT a control for it
- [PW patch series ↔ base are a matched pair](project_pw_patch_series_base_pairing.md) — bootstrap.diff applies ONLY to its own UPSTREAM_CONFIG SHA (0 vs 46-49 of 897 hunks); move both via `PW_WEBKIT_PATCHES_REF`; version parity with PW's shipped browser is unreachable
- [WebKit GTK headed recursion](project_webkit_gtk_headed_recursion.md) — PW SDK headed launch crashes MiniBrowser-gtk inside libgtk-4 with ~30-frame identical-PC infinite recursion at newPage time; WebKit code never runs; producer Tier-2 headed gated `if: false`; likely Xvfb-no-compositor or musl/glib main-loop quirk
- [JSC JIT PCH race on the new base](project_webkit_jsc_jit_pch_race.md) — 4d05d732's `JavaScriptCoreJIT` subtarget PCH doesn't depend on `JavaScriptCore_CopyPrivateHeaders` → `FPRInfo.h` not found; pre-build the header-copy targets
- [Our artifact's lib layout is FLAT](project_wk_artifact_flat_lib_layout.md) — every .so beside MiniBrowser with RPATH=$ORIGIN; `minibrowser-wpe/lib/` is PW's layout and assuming it cost two rounds; restore/stage with build-runner.sh's own whole-`/webkit` COPY
- [Pre-move WebKit needs its contemporary PW](project_wk_premove_build_needs_old_pw.md) — `wk-latest` hangs at newPage() under PW 1.62.1 (PushAPIEnabled), so a pre/post A/B can't hold the client constant; includes the payload-runner recipe
- [WK screenshot format ignored — RESOLVED](project_wk_screenshot_format_ignored.md) — `Page.snapshotRect` never plumbed `format`/`quality`, so every screenshot came back PNG (webp decode-failed, jpeg SOI-not-found, quality inert); webp-lib / dev-pkg / Skia-encoder hypotheses all dead
- [WebKit smoke sandbox strip layers](project_webkit_smoke_sandbox_strip_layers.md) — peel-by-error progression of Docker permissions for WebKit's bwrap: seccomp+apparmor+SYS_ADMIN → +NET_ADMIN → +WEBKIT_DISABLE_SANDBOX env
