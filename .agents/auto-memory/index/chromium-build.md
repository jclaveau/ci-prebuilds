# chromium-build — from-source rounds, gn args, caches, base images

Full hooks for this area. The routing keys live in `.agents/auto-memory/MEMORY.md`; the memories themselves in `.agents/auto-memory/<slug>.md`.

- [chromium round images are sha-keyed](project_chromium_round_images_sha_keyed.md) — any setup-layer edit = full cold r1..r12; cold chromium 151 is 25-30h (r1 boxed at 5h12m, 7578/38707), sccache hit rate ~1%
- [Chromium build time is cold-vs-warm, not PGO/LTO](project_chromium_build_time_is_cold_vs_warm_not_pgo.md) — 22 chains since July: before the knobs 36.1-44.5h, after 36.5-40.3h, single-variable pair 36.1 vs 40.7; the 3-8h runs everyone remembers are `reuse-if-exists` cache hits occurring on BOTH sides of the change, and an experiment can never reach that path; free lever is 4-6 concurrent chains, not disabling optimisations
- [sccache ghac: broken at 0.15, WORKS at 0.16](project_sccache_ghac_readonly_v18.md) — 0.15+opendal wrote the deprecated v1 path and flipped read-only; 0.16.0 + ACTIONS_CACHE_SERVICE_V2=1 reads and writes fine (1.33% on a cold cache, 210 write errors); don't quote the dead-backend state as current
- [chromium-from-source split-build](project_chromium_from_source_split_build.md) — GHA 6h hosted-runner cap kills chromium-148 cold build (~13h); split ninja into resumable Docker-layer rounds, obj/ persists via cache-to=registry; self-hosted REJECTED
- [chromium rounds are serial by construction](project_chromium_rounds_are_serial.md) — r2's BASE_IMAGE IS r1's obj/ layer, so r1..r12 can't be parallelized and the chop costs ~3s; levers are cores per round (4 vCPU today, billed to raise) and sccache, never scheduling
- [resume_from runs only r1 — silent green](project_resume_from_runs_only_r1.md) — `resume_from` skips setup; only r1 tolerates a skipped ancestor, so r2..finalize skip and the run reports SUCCESS having built nothing (32256708703)
- [chromium 151 gn peel](project_chromium_151_gn_peel.md) — `enable_print_preview` back ON (keep `use_cups=false`) + `pipewire-dev` for `//remoting`'s pkg_config; never `enable_remoting=false`
- [Finalize overlay for baked scripts](project_finalize_overlay_baked_scripts.md) — scripts are baked into the setup image; Dockerfile.finalize only re-COPYs SOME → an edit to a baked-but-not-overlaid script (e.g. stage-cache-layout.sh strip pass) is INERT on incremental dispatch; grep finalize for a fresh COPY before trusting a script edit shipped
- [chromium/webkit base-tag audit: SAFE](project_chromium_webkit_base_tag_audit_safe.md) — the FF pin-only-tag bug does NOT replicate in chromium (apk/from-source/headed) or webkit; all intermediate images sha-scoped + no iter/manifest-inspect auto-select; FF was the sole instance (PR #81 Q2)
- [Multi-job BASE_IMAGE audit](project_multijob_base_image_audit.md) — when adding a round to the chromium-from-source pipeline, audit ALL `BASE_IMAGE` build-args; finalize's stayed pinned to r3 for 4 iters while r4-r7 pushed unused images; look for chain-terminator mismatch when finalize's ninja progress "looks like" it started earlier than the last-round image
- [BuildKit cache-to commit semantics](project_buildkit_cacheto_commit_semantics.md) — `cache-to: type=registry,mode=max` only pushes when buildx exits NORMALLY; cancelled/killed builds publish nothing → next iter starts cold; multi-RUN split doesn't help, must shrink build to fit cap
- [Chromium-from-source Alpine runtime deps](project_chromium_from_source_runtime_deps.md) — validated apk list for chrome-headless-shell (chromium 148 musl); ~35 pkgs; names diverge from Debian (libatk-1.0/mesa-gbm/harfbuzz-subset)
- [Chromium VARIANT build](project_chromium_variant_build.md) — from-source pipeline parameterized headless|headed (ninja headless_shell vs chrome) via variant-config.sh; full chrome is a superset build, aports gn-args reference, minimal-headed args
